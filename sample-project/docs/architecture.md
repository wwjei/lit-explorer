# 架构说明

## 分层

1. **主进程** —— 唯一的系统访问入口。目录扫描、文件读取、默认程序打开、资源管理器定位都在这里
2. **预加载层** —— 通过 `contextBridge` 暴露白名单方法，渲染进程拿不到 Node 能力
3. **渲染进程** —— 纯界面逻辑：多栏导航、预览分派、虚拟滚动

## 为什么用自定义协议预览 HTML

直接用 `file://` 加载预览会把工作区之外的任意文件也暴露给预览页，
而且 `file://` 下的相对资源与跨源限制很难处理。这里注册了 `pv://` 协议：

- 所有请求都要通过 `assertAllowed()`，只能读已授权工作区内的文件
- 因为是标准协议，HTML 里的 `href="styles.css"` 这类相对路径能正常解析
- 响应头按扩展名给出正确的 Content-Type

## 性能取舍

- `readdir` 与 `stat` 分开：先返回条目名，大小/修改时间异步补发，首屏不等 IO
- 单栏条目超过 120 个时切换到虚拟滚动，DOM 行数恒定在可视范围
- 目录按需扫描：只有真正展开的那一栏才读磁盘

```js
const res = await pv.list(folder.path);   // 只读一层，不递归
```

> 渲染进程不做任何路径拼接，所有路径都来自主进程返回的绝对路径。
