# SVG 编辑与写入通道审查（2026-10-25）

> 对应 [FEATURES C26](../../FEATURES.md)（SVG 轻量编辑）与 [安全边界](../agents/security.md#svg-编辑的写入通道)。
> 之前的安全模型是「主进程只读」；这次第一次引入写文件，所以把边界、残余风险和验证记在这里。

## 1. 改变了什么

- `src/main/fs-api.js` 新增 `writeSvgFile()`：工作区内、已存在的 `.svg`、带版本基线
  （读取时的 `size` / `mtime`）、先写临时文件再 `rename`；
- `src/main/main.js` 新增 IPC `fs:write-svg`，`preload.js` 只暴露 `writeSvg()`；
- `src/renderer/svgedit.js` 新增编辑模式：把 SVG 解析成 DOM 挂进宿主页面，
  支持改字、拖动、矩形缩放、删除与撤销，每次改动自动保存。

## 2. 威胁与对策

| 威胁 | 对策 | 验证 |
| --- | --- | --- |
| 恶意 SVG 在宿主页面执行脚本 / 读取工作区 / 调 `pv` | 进入 DOM 前摘掉 `<script>`、`foreignObject`、`iframe` / `object` / `embed`、SMIL、`on*` 事件属性、`javascript:` / `vbscript:` / 危险 `data:` 链接、`file:` / 相对资源引用，以及 CSS 的 `@import` / 外部 `url()`；一旦摘掉东西就标为只读，不提供保存 | E3：脚本元素、`onload`、`javascript:` 链接都不在 DOM 里，脚本没有执行 |
| 编辑模式里的 `<a>` 把应用窗口导航走 | 捕获阶段拦截 `click` / `auxclick`，`preventDefault()`；不提供「在浏览器打开」的默认行为 | E3 的链接被摘掉；手工点击不跳转 |
| 渲染进程借保存能力写工作区外的文件 | `assertAllowed()` 走 `realpath`，junction / 符号链接越不过去；写入口只此一个 | E2：工作区外返回 `EACCES_ROOT` |
| 借保存能力写非 SVG / 新建任意文件 | 扩展名必须是 `.svg`，目标必须是已存在的普通文件 | E2：`.txt` 返回 `ENOT_SVG` |
| 覆盖别人的修改（agent / 编辑器重新导出） | 调用方带 `{ size, mtime }`，不一致返回 `CONFLICT`，文件不动 | E2：旧基线返回 `CONFLICT`，内容未变 |
| 写入中途崩溃留下半个文件 | 同目录临时文件 + `rename`，失败清理临时文件 | 代码路径；探针实际写回样例 |
| 只读模式下保存把原文件里的脚本悄悄删掉 | 清洗时只要摘掉了东西就禁止保存；只读模式不接指针手势、`Delete` 无效 | E3：只读状态、`Delete` 不删形状、写入 0 次 |
| 大文件 / 编码不可识别导致重写损坏 | 超 5 MB、`truncated`、`lossy`，或检测到 GBK / XML 声明指向非 UTF-8 时进入编辑只显示卡片，不提供保存 | E2：GBK 文件读出 `encoding: gbk`，编辑器据此拒绝保存 |

## 3. 残余风险

- **自动保存**：每次手势 / 文字提交都会写盘。`Ctrl+Z` 可在当前编辑会话里撤销，但关掉
  「完成」（退出编辑模式）后撤销栈不再保留。已经在 README / FEATURES 里写明。
- **同目录临时文件**：`rename` 会替换原文件，Windows 上 ACL / 备用数据流等元数据可能不被
  保留（普通截图 / 图表文件通常无关）。没有现成的跨平台「保留 ACL 的原子替换」。
- **启发式分组**：拖动矩形时按「文字中心落在矩形内」把同级的 `<text>` 一起带走；
  重叠布局可能误带相邻文字。删除同理。不是 `g` 结构的图里这是最省事也最可预期的规则。
- **序列化差异**：保存会重新序列化（保留 XML 声明、BOM、结尾换行），属性顺序、缩进、
  注释位置会被规范化；`<script>` 等不安全内容的文件根本不会进入可保存状态。
- **TOCTOU**：冲突检查与实际 `rename` 之间仍有极短窗口；本地单用户场景接受。

## 4. 怎么验证

```bash
npm run test:integration -- --only=E1,E2,E3
```

- E1：改字、拖动（带框内文字）、矩形缩放、删除（带框内文字）、撤销，每次改动都走
  `fs:write-svg` 桩，断言写回内容与版本基线；
- E2：真实磁盘上的保存、`.txt` / 工作区外拒绝、冲突不覆盖、保存后新基线可用；
- E3：含脚本 / 事件属性 / `javascript:` 链接的 SVG 只读、不执行、不写文件；
- E4：用 `webContents.sendInputEvent` 发真实鼠标事件双击文字，断言输入框出现并带着原文。
  这一条是补上的：之前只在测试里合成 `dblclick`，漏掉了「指针捕获设在 stage 上会把
  `mouseup` / `click` / `dblclick` 重定向，导致真实双击目标变成 stage」的问题。

界面探针另外用 `fig-2.1-layers-packages.svg` 走了一遍真实主进程保存：
改字、拖框、缩放、删除、撤销后，文件里能搜到 `Comate 包（改）`、`width="502.88"` 与
`transform="translate(...)"`，矩形数量与撤销前一致。
